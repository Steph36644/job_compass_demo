# 求职追踪网站 V1.0 PRD（MVP · 个人使用版）

> 文档性质：产品需求文档（PRD）
> 版本：V1.0（MVP）｜日期：2026-09-20
> 关联文档：《求职追踪网站_需求分析报告.md》
> 产品暂定名：**求职罗盘**（Job Compass）
> 适用范围：本 PRD 仅定义 V1.0 MVP，面向**个人用户单账号使用**，不含团队协作、B 端院校看板等功能

---

## 一、产品概述

### 1.1 产品定位

面向中国应届生与实习生的**个人 AI 求职过程管理工具**：把分散在表格、备忘录、邮箱里的投递信息集中管理，用 AI 完成"岗位要求 × 个人简历"的差距分析与求职复盘，帮助用户回答三个问题——**我投到哪了、我还缺什么、下一步该做什么**。

### 1.2 版本目标

V1.0 MVP 只验证并跑通一条个人核心闭环：

> **粘贴 JD 秒建档 → 查看匹配度与能力缺口报告 → 看板流转状态并接收笔面试提醒 → 周末看 AI 复盘，据此改简历、调方向**

**成功标准（MVP 验收后 4 周内观察）**：
- 新用户首次建档完成率 ≥ 60%（注册 → 至少保存 1 条投递）
- JD 解析字段准确率 ≥ 85%（核心字段：公司、岗位、城市、要求）
- 周活跃用户中，查看匹配报告的比例 ≥ 70%
- 周留存 ≥ 40%（求职季中）

### 1.3 核心价值主张（对个人用户）

1. **不遗漏**：所有投递集中管理，笔面试时间自动提醒，告别"投完就忘"
2. **不盲投**：每个岗位 AI 给出匹配度与缺失项，投之前知道差距
3. **能复盘**：漏斗数据 + AI 周报，用数据回答"该改简历还是换方向"

### 1.4 本版本明确不做的功能边界

以下功能在 V1.0 **明确不做**，避免范围蔓延：

| 不做的功能 | 原因 |
|---|---|
| 浏览器插件一键抓取 | 已确认延后至 V2；MVP 用粘贴 JD 解析替代 |
| 邮箱/短信自动解析通知 | 需强授权、开发量大，V2 再做 |
| 多人协作 / 团队看板 / 数据共享 | 个人工具定位，无协作需求 |
| B 端院校 / 培训机构看板 | 第二曲线，V2 后评估 |
| 自建岗位库 / 职位聚合 / 薪资查询 | 偏离"管理"主线，可通过粘贴 JD 覆盖信息入口 |
| 求职社区 / 匿名爆料 / 面经广场 | 冷启动与审核成本高，与核心闭环无关 |
| AI 自动批量投递 / 海投机器人 | 合规风险高，且违背"精准投递"价值观 |
| AI 全自动代写简历经历 | 幻觉造假风险，只做基于真实经历的改写建议 |
| 模拟面试 / 求职信生成 | 单点能力，非差异化核心，V2 后 |
| Offer 对比决策器 | 求职末期场景，V2 后 |
| 小程序 / App | MVP 仅 Web 端（响应式适配移动端浏览器） |

## 二、目标用户

### 2.1 核心目标用户（P0）

**中国大陆应届毕业生**（大三暑期实习、大四秋招/春招、研二研三）

- 画像特征：
  - 年龄 21–26 岁，本/硕在读或应届
  - 单人求职周期 2–4 个月，投递量 30–200 份
  - 当前用 Excel/飞书表格/备忘录记录投递，维护困难且容易放弃
  - 对 AI 工具接受度高（应届生 65.9% 已用 AI 辅助求职）
  - 付费能力有限，对工具定价敏感，倾向低价或免费
- 核心诉求：
  - 不再遗漏投递进度与笔面试时间
  - 知道每个岗位自己匹配度如何、缺什么
  - 投了很多没面试时，能定位问题并改简历/调方向

### 2.2 次要目标用户（P1）

- 找日常实习/暑期实习的低年级学生（大二大三）
- 毕业 1 年内仍在求职的人群

### 2.3 用户核心诉求总结

| 诉求 | 对应功能 |
|---|---|
| 记录所有投递（公司/岗位/日期/渠道/结果） | 投递台账 + 状态看板 |
| 不漏掉笔面试与网申截止 | 日程提醒 |
| 快速录入，不花太多时间 | 粘贴 JD AI 解析建档 |
| 知道我和这个岗位差在哪、怎么补 | JD×简历匹配报告 + 缺口行动建议 |
| 复盘整个求职过程，改善简历或方向 | 漏斗仪表盘 + AI 周复盘 |

## 三、整体信息架构

### 3.1 一级导航

MVP 采用左侧导航（桌面端）/ 底部 Tab（移动端适配），共 5 个一级入口：

```
求职罗盘
├── 看板（Dashboard / Kanban）   ← 默认首页
├── 投递记录（All Applications）  ← 列表视图
├── 简历（Resumes）               ← 简历中心
├── 数据洞察（Insights）          ← 漏斗 + 周复盘
└── 我的（Profile）               ← 求职档案、设置
```

**全局固定操作**：右上角「+ 新建投递」按钮（任意页面可快速建档）。

### 3.2 核心数据实体关系

```
用户 User (1)
  ├── 求职档案 Profile (1)
  ├── 简历 Resume (1..N)
  │     └── 简历段落 ResumeSection (教育/经历/技能/项目...)
  └── 投递 Application (0..N)
        ├── JD 原文 + 结构化 JD (1)
        ├── 关联简历版本 (1, 可选)
        ├── 状态流转记录 StatusLog (1..N)
        ├── 日程 Schedule (0..N, 笔试/面试/截止)
        ├── 复盘 Review (0..1)
        └── AI 匹配报告 MatchReport (0..1)
```

## 五、详细功能需求

### 5.1 账号与求职档案

#### 5.1.1 注册/登录

**目标**：让用户以最低成本完成身份建立，数据可跨设备同步。

**功能点**：
- 手机号 + 短信验证码登录/注册（同一流程，未注册自动创建账号）
- 登录后默认进入「看板」页
- 支持退出登录、注销账号（注销后 30 天内可恢复，之后数据彻底删除）

**字段**：
| 字段 | 说明 | 必填 |
|---|---|---|
| 手机号 | 中国大陆 11 位手机号 | 是 |
| 验证码 | 6 位数字，5 分钟有效 | 是 |

**非功能要求**：
- 验证码 60 秒内不可重复发送
- 同一手机号 1 小时内最多发送 5 次验证码

#### 5.1.2 求职档案

**目标**：为 AI 分析与方向建议提供用户上下文。

**功能点**：
- 首次登录强制引导填写求职档案（可跳过，但后续建档时再次提示）
- 档案可在「我的」中随时修改

**字段**：
| 字段 | 类型 | 说明 | 必填 |
|---|---|---|---|
| 昵称 | 文本 | 显示用 | 否 |
| 学校 | 文本 | 自由填写 | 是 |
| 专业 | 文本 | 自由填写 | 是 |
| 学历 | 下拉 | 大专/本科/硕士/博士 | 是 |
| 毕业年份 | 年份 | 如 2027 | 是 |
| 目标方向 | 文本/标签 | 如"产品经理、运营"，可多个 | 是 |
| 期望城市 | 文本/标签 | 可多个 | 否 |
| 求职阶段 | 单选 | 实习/秋招/春招/社招 | 是 |

---

### 5.2 简历中心

#### 5.2.1 简历上传解析

**目标**：将用户简历转化为结构化数据，供 AI 匹配使用。

**功能点**：
- 支持上传 PDF、Word（.docx）格式，单文件 ≤ 10MB
- 上传后自动解析为结构化简历（教育背景、工作/实习经历、项目经历、技能、自我评价等段落）
- 解析结果进入可编辑页面，用户可手动修改任意字段（**解析只是辅助，人工校正为最终数据**）
- 解析失败（文件损坏/格式不支持）时，提示用户手动填写

**解析输出结构**（供 AI 匹配使用）：
```
{
  "education": [{ "school": "", "major": "", "degree": "", "start": "", "end": "", "description": "" }],
  "experiences": [{ "company": "", "position": "", "start": "", "end": "", "bullets": ["", ""] }],
  "projects": [{ "name": "", "role": "", "description": "", "technologies": [""] }],
  "skills": ["", ""],
  "self_intro": ""
}
```

#### 5.2.2 多版本管理

**功能点**：
- 支持创建多个简历版本，每个版本可命名（如"产品经理版""运营版""通用版"）
- 列表展示所有版本：名称、创建时间、最后修改时间、关联投递数
- 投递建档时可选择关联的简历版本（可选）
- 默认设置一个"主简历"版本

**非功能要求**：
- 单个用户最多 10 个简历版本
- 简历原文文件加密存储

### 5.3 投递建档

#### 5.3.1 粘贴 JD 智能解析建档（主入口）

**目标**：无插件阶段的核心录入方式，把录入时间从 5 分钟降到 10 秒。

**交互流程**：
1. 用户点击「+ 新建投递」，默认进入"粘贴 JD"模式
2. 用户粘贴 JD 文本（或粘贴岗位链接，系统尝试抓取正文）
3. 点击「解析」，系统 AI 抽取字段（加载态展示骨架屏，≤ 15 秒）
4. 解析结果回填到可编辑表单，用户核对修改
5. 点击「保存」完成建档，自动进入该投递详情页

**AI 解析抽取字段**：
| 字段 | 说明 |
|---|---|
| 公司名称 | |
| 岗位名称 | |
| 工作城市 | 可多个 |
| 薪资范围 | 结构化（如 15-25K·14薪） |
| 学历要求 | 本科/硕士等 |
| 经验要求 | 应届生/1-3年等 |
| 工作职责 | 列表 |
| 任职要求 | 列表，区分硬性/加分项 |
| 关键词/技能 | 列表 |

**降级与容错**：
- 解析失败时，保留用户粘贴的 JD 原文，进入手动表单，JD 原文已填入对应字段
- 链接抓取失败时，提示用户手动复制 JD 文本
- 解析结果每个字段都可编辑

#### 5.3.2 手动表单建档

**目标**：JD 解析的补充，覆盖无法解析的场景。

**功能点**：
- 用户可切换到"手动填写"模式
- 展示完整投递表单（字段见 5.4.1）
- JD 原文为必填（用于后续 AI 匹配）

#### 5.3.3 防重复提醒

- 保存时检测同公司 + 同岗位是否已存在（忽略大小写与空格）
- 若存在，弹窗提示「该岗位已建档，是否查看？」，用户可选择查看或仍新建

### 5.4 状态看板与投递台账

#### 5.4.1 投递记录字段字典

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 公司名称 | 文本 | 是 | |
| 岗位名称 | 文本 | 是 | |
| 投递渠道 | 下拉+自定义 | 是 | Boss直聘/牛客/实习僧/官网/内推/脉脉/其他 |
| 投递日期 | 日期 | 是 | 默认今天 |
| 内推人 | 文本 | 否 | |
| 工作城市 | 文本/标签 | 否 | |
| 薪资范围 | 文本 | 否 | |
| 岗位链接 | URL | 否 | |
| JD 原文 | 长文本 | 是 | 粘贴或解析来源 |
| 关联简历版本 | 关联 | 否 | 下拉选择已有简历 |
| 当前状态 | 枚举 | 是 | 见 5.4.2 状态机 |
| 备注 | 长文本 | 否 | |
| 结构化 JD | 对象 | 否 | AI 解析产物，展示用 |

#### 5.4.2 状态机定义

**状态枚举**（国内校招真实流程）：

| 状态 | 含义 | 是否终态 |
|---|---|---|
| 待投递 | 已收藏但未投 | 否 |
| 已投递 | 简历已投出，等待反馈 | 否 |
| 测评/笔试 | 收到在线测评或笔试通知 | 否 |
| 面试中 | 进入面试流程（可记多轮） | 否 |
| Offer | 已收到 Offer | 是（可继续操作） |
| 已被拒 | 明确收到拒信或流程终止 | 是 |
| 已终止 | 主动放弃或流程超时关闭 | 是 |

**状态流转规则**：
- 允许正向流转：待投递 → 已投递 → 测评/笔试 → 面试中 → Offer
- 允许跳级（如已投递直接到 Offer）
- 允许回退（如面试中 → 已投递，因流程重启）
- 终态（Offer/已被拒/已终止）可重新激活回非终态
- 每次状态变更自动生成一条 StatusLog（时间 + 旧状态 + 新状态 + 备注）

**状态颜色**：待投递(灰)、已投递(蓝)、测评笔试(紫)、面试中(橙)、Offer(绿)、已被拒(红)、已终止(灰深)

#### 5.4.3 看板视图

**功能点**：
- 按状态分列展示投递卡片，支持拖拽流转
- 卡片信息：公司名、岗位名、城市、投递日期、关联简历版本标识、最后更新时间
- 每列顶部显示该状态数量
- 点击卡片进入投递详情页
- 支持按目标方向、城市、渠道筛选（顶部筛选栏）
- 空状态：引导用户「+ 新建投递」

#### 5.4.4 列表视图（投递记录页）

**功能点**：
- 表格展示所有投递记录，支持按字段排序
- 列：公司、岗位、渠道、城市、投递日期、当前状态、最后更新、操作
- 支持搜索（公司名/岗位名）
- 支持筛选（状态、渠道、城市、方向、时间范围）
- 支持批量操作（批量删除、批量改状态）— MVP 仅做批量删除

### 5.5 日程提醒

#### 5.5.1 日程管理

**目标**：防止错过笔面试与网申截止。

**功能点**：
- 在投递详情页可添加日程，类型：笔试、面试、网申截止、其他
- 日程字段：类型、时间、地点/链接、备注
- 一个投递可关联多个日程（如一面、二面）
- 看板/列表中，临近日程（≤ 3 天）的卡片显示红点提醒
- 投递详情页展示该投递的所有日程时间线

#### 5.5.2 提醒规则

| 触发条件 | 提醒方式 | 说明 |
|---|---|---|
| 日程前 24 小时 | 站内 + 邮件 | 笔试/面试/截止均提醒 |
| 日程前 2 小时 | 站内 | 面试重点提醒 |
| 投递 7 天无反馈且状态为"已投递" | 站内 + 邮件 | 提示是否跟进 HR |
| 网申截止前 1 天 | 站内 + 邮件 | 防止错过截止 |

**MVP 范围**：站内提醒（页面内通知中心）+ 邮件提醒。微信服务号通知为 V1.1。

**邮件要求**：
- 用户需在「我的」中绑定并验证邮箱
- 未绑定邮箱则仅站内提醒
- 邮件需包含：公司、岗位、日程类型、时间、地点/链接、投递详情页链接

### 5.6 JD×简历 AI 匹配报告

#### 5.6.1 触发方式

- 投递建档时，若已关联简历版本，自动生成匹配报告（可关闭自动生成）
- 投递详情页可手动点击「生成/重新生成匹配报告」
- 未关联简历时，提示用户先选择简历版本

#### 5.6.2 报告输出结构

**1. 匹配度概览**
- 综合匹配度：百分比（仅参考，不做绝对判定）
- 三句话摘要：① 整体匹配情况 ② 主要优势 ③ 主要缺口

**2. JD 要求结构化清单**

按四类分组展示，每条要求标注匹配状态：

| 类别 | 说明 |
|---|---|
| 硬性要求 | 学历、经验年限、必备技能等"不满足即淘汰"项 |
| 岗位职责 | 该岗位要做什么，匹配用户过往职责的相似度 |
| 技能要求 | 工具、技术栈、软技能 |
| 加分项 | 非必须但有则加分的项 |

**每条要求的展示**：
```
[要求原文]  [匹配状态：已具备/部分具备/缺失]
  └─ 简历证据：引用简历中对应的具体段落原文（已具备/部分具备时显示）
  └─ 行动建议：缺失时给出建议（见 5.6.3）
```

**3. 能力缺口与行动建议**（核心差异化）

将所有"缺失"和"部分具备"项汇总，转化为可执行的行动：

| 建议类型 | 示例 |
|---|---|
| 补项目经历 | "该岗位要求『用户调研』，建议补充一个包含用户调研方法的项目经历，可参考：竞品分析 + 用户访谈 + 调研报告输出" |
| 学技能 | "要求熟练使用 SQL，建议学习 SQL 基础查询与聚合，可在 LeetCode SQL 专题练习" |
| 优化简历表述 | "你的经历有数据分析内容但未体现，建议在 XX 经历中加入具体数据指标（如转化率提升 X%）" |
| 调整投递方向 | "该岗位硬性要求硕士学历，与你本科背景不匹配，建议调整方向或寻找本科可投的同类岗位" |

**4. 简历优化建议**
- 针对本次岗位，给出简历具体修改点（非全文重写）
- 每条建议标注：修改位置、当前表述、建议表述、修改理由

#### 5.6.3 AI 输出安全规范（防幻觉红线）

- **每条匹配判定必须双向引用**：JD 原文片段 + 简历原文片段，用户可点击展开查看
- **不生成虚构经历**：行动建议中"补项目经历"只给方向，不编造具体项目内容
- **不编造数据**：简历优化建议中涉及数据时，标注"请填入你真实的数据"
- **明确免责声明**：报告底部显示"本报告由 AI 生成，仅供参考，请人工核对后使用"
- **提供反馈入口**：每条判定旁可点"不准确"，收集反馈用于迭代

#### 5.6.4 非功能要求

- 单份报告生成时间 ≤ 30 秒（超时提示重试）
- 免费用户每月生成报告额度：10 份（超出提示升级，MVP 阶段可先全免费，额度控制为后续商业化预留）
- 报告生成失败时保留上次成功的报告

### 5.7 单岗位复盘

**目标**：沉淀面试/被拒原因，为漏斗分析提供结构化数据。

**功能点**：
- 投递详情页中「复盘」区域，状态进入终态（Offer/已被拒/已终止）或面试后可填写
- 字段：

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 面试轮次 | 数字 | 否 | 第 N 面 |
| 考察问题 | 长文本 | 否 | 记录被问到的问题 |
| 自评表现 | 下拉 | 否 | 很好/一般/不好 |
| 被拒原因 | 多选标签 | 否 | 学历不符/经验不足/技能不匹配/薪资期望/方向不符/表达问题/其他 |
| HR 反馈 | 长文本 | 否 | 官方或 HR 告知的原因 |
| 复盘总结 | 长文本 | 否 | 自由文本反思 |

- 被拒原因标签用于仪表盘聚合分析

### 5.8 求职漏斗仪表盘

**目标**：用数据让用户看见自己的求职转化情况。

**展示内容**：

**1. 核心指标卡片**
- 总投递数
- 笔试通过率 = 测评/笔试数 / 已投递数
- 面试通过率 = 面试中+Offer数 / 已投递数
- Offer 数
- 平均响应天数 = (各投递首次反馈日期 - 投递日期) 的均值

**2. 转化漏斗图**
```
已投递 ──→ 测评/笔试 ──→ 面试中 ──→ Offer
  60         12 (20%)       5 (8.3%)     2 (3.3%)
```
- 每阶段显示数量与转化率

**3. 分维度对比表**
- 按渠道：各渠道的投递数与面试率
- 按目标方向：各方向的投递数与面试率
- 按城市：各城市的投递数与面试率
- 按简历版本：各版本的投递数与面试率

**4. 时间趋势**
- 近 4 周投递量趋势折线图

**MVP 简化**：核心指标 + 漏斗图 + 分维度表格（用数据表格替代复杂图表，降低开发量）。趋势图可为可选。

### 5.9 AI 周度复盘报告

**目标**：每周自动生成求职复盘，给出可执行建议，建立"教练"心智。

#### 5.9.1 触发方式
- 每周一凌晨自动生成上周（周一至周日）复盘报告
- 用户可在「数据洞察」页查看历史所有周报
- 仅当用户上周有投递或状态更新时生成（无数据则跳过）

#### 5.9.2 报告输出结构

**1. 本周数据概览**
- 本周新增投递数、状态变更数
- 漏斗当前状态

**2. 漏斗诊断**
- 自动判断瓶颈环节：
  - 若笔试率 < 10%：瓶颈在简历初筛，建议优化简历匹配度
  - 若笔试率高但面试率低：瓶颈在笔试/测评，建议刷题
  - 若面试率高但 Offer 少：瓶颈在面试，建议复盘面试问题
- 引用具体数据支撑判断

**3. 简历修改建议**
- 基于本周被拒/未回复岗位的共同缺失项，汇总 Top 3 简历优化点
- 引用具体岗位的匹配报告结论

**4. 投递方向调整建议**
- 基于本周各方向回复率，建议：
  - 加大回复率高的方向投递
  - 减少或停止回复率持续为 0 的方向
  - 数据不足时提示"样本太少，建议继续投递积累数据"

**5. 下周行动清单**
- 3–5 条具体可执行项，如：
  - "优化产品方向简历，补充用户调研相关项目"
  - "本周投递目标 10 份，重点关注北京的产品岗"
  - "准备 XX 公司的面试，复习 SQL 与数据指标"

#### 5.9.3 安全规范
- 所有数据结论必须引用用户自身数据，不编造
- 方向建议仅基于用户回复率，不做绝对断言
- 底部免责声明

## 六、关键交互流程

### 6.1 核心主线流程（首次使用）

```
注册/登录
  → 填写求职档案（可跳过）
  → 上传简历（可跳过，建档时提示）
  → 看板空状态 → 点击「+ 新建投递」
  → 粘贴 JD → 解析 → 核对 → 保存
  → 自动生成匹配报告 → 查看报告
  → 拖拽状态流转（待投递→已投递）
  → 收到笔试通知 → 添加日程 → 收到提醒
  → 周末 → 数据洞察 → 查看 AI 周复盘
  → 根据建议改简历/调方向 → 继续投递
```

### 6.2 建档流程详细时序

| 步骤 | 用户操作 | 系统响应 |
|---|---|---|
| 1 | 点击「+ 新建投递」 | 打开建档页，默认"粘贴 JD"模式 |
| 2 | 粘贴 JD 文本，点「解析」 | 显示加载态，调用 AI 解析接口 |
| 3 | 解析完成 | 回填表单，JD 原文保留 |
| 4 | 用户核对修改字段 | — |
| 5 | 点「保存」 | 校验必填，防重复检测 |
| 6 | 保存成功 | 跳转投递详情页，若有简历则自动生成匹配报告 |
| 7 | 查看匹配报告 | 展示报告，用户可点"不准确"反馈 |

## 七、界面设计要求

### 7.1 整体交互风格

- **定位**：工具型产品，效率优先，减少装饰
- **风格关键词**：简洁、清晰、克制、可信赖
- **配色**：主色蓝/青（冷静专业），状态色区分明确（绿/橙/红/蓝）
- **信息密度**：中高（求职期用户需要快速浏览大量投递）
- **动效**：极少量，仅用于状态流转反馈

### 7.2 核心页面设计原则

| 页面 | 设计原则 |
|---|---|
| 看板页 | 状态分列清晰，卡片信息一眼可读，拖拽反馈明确；空状态引导建档 |
| 建档页 | 解析结果与可编辑表单同屏，JD 原文与解析字段左右对照；重点字段高亮 |
| 匹配报告页 | 要求清单为主，匹配状态用颜色/图标区分；行动建议醒目展示；证据可展开折叠 |
| 数据洞察页 | 核心指标置顶，漏斗图直观，分维度表格可排序筛选 |
| 周复盘页 | 结论先行，数据支撑，行动清单可勾选完成 |

### 7.3 关键交互规范

1. **状态流转**：看板拖拽即流转，无需二次确认；支持撤销（5 秒内 toast 提示"已流转，撤销"）
2. **建档**：解析中显示骨架屏，禁止重复点击；解析失败不丢失用户输入
3. **AI 报告**：生成中显示进度，失败可重试；报告内容支持复制
4. **提醒**：站内通知中心在顶部铃铛，未读数红点
5. **移动端适配**：看板在窄屏改为列表（按状态分组），操作按钮置于底部

## 八、非功能性需求

### 8.1 性能

| 指标 | 要求 |
|---|---|
| 页面首屏加载 | ≤ 3 秒（常规网络） |
| JD 解析响应 | ≤ 15 秒返回结构化结果 |
| 匹配报告生成 | ≤ 30 秒 |
| 看板加载（100 条投递） | ≤ 2 秒 |

### 8.2 安全与合规（红线）

- **数据加密**：简历原文、JD 原文等敏感数据传输与存储加密（AES-256 存储，HTTPS 传输）
- **最小化采集**：仅收集功能必需数据，不收集无关信息
- **AI 调用脱敏**：简历中姓名、电话、邮箱等 PII 在调用 AI 前脱敏处理
- **用户控制权**：支持一键删除单条投递、删除简历版本、注销账号（30 天可恢复，之后彻底删除）
- **隐私政策与用户协议**：注册时强制阅读并同意
- **数据归属**：用户数据归用户所有，不用于未经授权的第三方用途；B 端数据严格匿名聚合（V1 不涉及）
- **符合《个人信息保护法》要求**

### 8.3 兼容性

- 桌面端：Chrome、Edge、Safari 最新 2 个版本
- 移动端：iOS Safari、Android Chrome（响应式适配，非独立 App）
- 分辨率：最小支持 375px 宽度

### 8.4 可用性

- 所有 AI 生成内容明确标注"AI 生成"
- 所有删除操作二次确认
- 关键操作有加载态与失败重试

## 九、版本排期参考

### 9.1 开发优先级顺序

建议按依赖关系分 4 个 Sprint（每个 Sprint 约 2 周，共约 8 周）：

| Sprint | 模块 | 内容 | 产出 |
|---|---|---|---|
| **Sprint 1** | 基础 | 账号登录、求职档案、简历上传解析、投递建档（手动+JD解析）、投递台账 | 可建档、可管理简历 |
| **Sprint 2** | 追踪 | 状态看板（含拖拽）、状态机、投递列表、单岗位复盘 | 完整投递追踪闭环 |
| **Sprint 3** | 智能 | JD×简历匹配报告、能力缺口行动建议 | AI 核心能力上线 |
| **Sprint 4** | 决策 | 日程提醒、漏斗仪表盘、AI 周度复盘、全局打磨 | 完整 MVP 闭环 |

### 9.2 依赖关系

- 简历解析（S1）是匹配报告（S3）的前置
- 投递建档（S1）是看板（S2）的前置
- 状态数据（S2）是漏斗与周复盘（S4）的前置
- JD 结构化数据（S1）是匹配报告（S3）的前置

### 9.3 建议先做技术验证（Spike）

在 Sprint 1 启动前，用 3–5 天验证：
1. **JD 解析准确率**：取 100 条真实校招 JD（覆盖技术/产品/运营/金融/制造），验证字段抽取准确率是否 ≥ 85%
2. **简历解析效果**：取 20 份真实学生简历，验证结构化解析质量
3. **AI 匹配判定效果**：验证 5.6.2 的输出结构是否合理、是否存在明显幻觉

## 十一、风险与待确认项

### 11.1 主要风险

| 风险 | 等级 | 应对 |
|---|---|---|
| JD 解析准确率不达标 | 高 | 前置 Spike 验证；人工校正兜底；持续优化 Prompt 与模型 |
| AI 匹配报告可信度低 | 高 | 双向引用原文；用户反馈机制；只给建议不给绝对结论 |
| 无插件导致录入摩擦大 | 高 | JD 解析作为主入口降低成本；V1.1 加速插件开发 |
| 用户拿 Offer 后流失 | 中 | 低年级实习场景提前获客；求职档案沉淀；后续实习转正跟踪 |
| AI 调用成本 | 中 | JD 解析结果缓存复用；按次额度；解析用小模型、复盘用强模型 |
| 数据安全合规 | 高（红线） | 加密、脱敏、用户控制权、隐私协议前置 |

### 11.2 待确认项（需在开发前明确）

1. **AI 模型选型**：用哪家大模型（建议国产合规模型，如豆包/通义/DeepSeek），需评估中文 JD 解析效果与成本
2. **登录方式**：是否同时支持微信扫码登录（需企业资质与开发者账号），还是 MVP 仅手机号
3. **邮件发送服务**：用哪家邮件服务商（如 SendCloud/腾讯云邮件），需评估送达率
4. **商业化时机**：MVP 阶段匹配报告是否完全免费，还是设额度（建议 MVP 全免费验证留存，V1.1 再设额度）
5. **部署环境**：国内服务器需 ICP 备案，域名与服务器选型
