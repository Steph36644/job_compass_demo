# 求职罗盘 V1.1 PRD（前端补全）

> 文档性质：产品需求文档（PRD）
> 版本：V1.1｜日期：2026-10-04
> 关联文档：《docs/求职追踪网站_V1.0_PRD.md》《docs/求职追踪网站_需求分析报告.md》

## 一、版本说明与范围

### 1.1 版本主题

**前端补全：建档、修改、回顾都能在界面里完成。**

V1.0 已铺齐五个主页面（看板、投递记录、新建投递、简历、数据洞察、我的），主路径可以走通，但存在一批会让演示和日常使用「露馅」的断点：详情页刷新后打不开、建档后无法修改、重复建档卡死、简历多段经历保存即丢失、空数据时展示写死的示例结论。V1.1 不加新模块，只把已有流程补完整。

### 1.2 本版明确不做

| 不做项 | 原因 |
|---|---|
| 账号体系 / 后端 / 数据库 | 当前用户为开发者本人，localStorage 已满足 |
| 真实大模型接入（JD 解析、匹配报告、周复盘） | 前端流程稳定后再替换 `mock-ai`，接口形状不变 |
| 浏览器插件、微信通知、邮件提醒 | V2 自动化事项 |
| 能力缺口聚合图谱、日历视图、校招批次日历 | 第二轮/第三轮及以后 |
| 漏斗统计口径修正（按状态日志计算转化） | 列入第二轮，本版仅收敛空状态展示 |
| Excel/JSON 导入导出 | 列入第三轮 |

### 1.3 成功标准

- 从「粘贴 JD → 核对修改 → 保存 → 改状态 → 编辑信息 → 记复盘」全流程无阻断点
- 直接刷新任意详情页可正常打开
- 真实多段简历可完整录入、编辑、保存，字段不丢失
- 空数据状态下不出现任何写死的示例数字

## 二、现状问题清单

以下问题均已在代码中定位，作为本版需求的直接依据。

### P1 详情页未订阅数据，刷新即失效

`v1.0/job-compass/src/app/applications/[id]/page.tsx` 第 21 行使用 `getApplication(id as string)` 一次性读取缓存，未通过 `useStore` 订阅：

- localStorage 水合（`hydrate`）发生在挂载后，直接刷新详情网址时缓存尚为空，页面显示「投递记录不存在」
- 页内调用 `changeStatus` 后，`app` 引用不更新，状态下拉框仍显示旧值，与时间线（已订阅）表现不一致

### P2 重复建档「仍要新建」走不通

- `v1.0/job-compass/src/app/applications/new/page.tsx` 的 `handleSave`（约 159 行）先调 `checkDuplicate`，命中则置 `dupWarning`；但「仍要新建」按钮（约 261 行）再次调用 `handleSave`，重复检查再次命中，保存永远无法完成
- 即使跳过前端检查，`v1.0/job-compass/src/lib/store.ts` 的 `addApplication`（131–135 行）发现同公司同岗位时静默 `return d`，数据根本不写入

### P3 手填模式误显示「AI 已解析」提示

`new/page.tsx` 的 `ApplicationForm`（约 186 行）无条件渲染「AI 已解析以下字段，请核对后保存」横幅，手动填写模式（无解析结果）同样出现，误导用户。

### P4 简历表单装不下多段经历，保存即丢数据

`v1.0/job-compass/src/app/resumes/page.tsx` 的 `ResumeForm` 只读写 `education[0]`（约 193 行）、`experiences[0]`（约 206 行）、`projects[0]`（约 220 行）：

- 种子数据 `v1.0/job-compass/src/lib/mock-data.ts`（30–63 行）中简历含完整多字段结构，一经编辑保存，经历的公司、职位、起止时间被清空，多段被压成一段
- 简历结构化数据是匹配报告的输入源，该问题直接损害 AI 功能的数据基础

### P5 洞察页无数据时展示写死的示例周报

`v1.0/job-compass/src/app/insights/page.tsx` 的 `WeeklyReviewSection`（约 171 行）在无周报时回退到 `generateMockWeeklyReport()`（226 行起），展示「本周投递 8 份、面试率 25%」等虚构数字，与真实数据混淆。

### P6 看板七列平铺，空状态重复

- `v1.0/job-compass/src/components/kanban/KanbanBoard.tsx`（13–21 行）将 7 个状态全部作为列平铺，桌面端需横向滚动，「已被拒 / 已终止」等结束态与进行中状态混杂
- 无投递时，首页空引导（`page.tsx` 44–57 行）与七列空看板（每列显示「拖拽到此」）同时出现，视觉重复

### P7 建档后无法编辑投递信息

`store.ts` 已有 `updateApplication`（149 行），但详情页与列表页均无编辑入口。解析错公司名只能删除重建；`Application.referrer`（内推人，`types.ts` 111 行）在类型中已定义，表单中只能混写在备注里。

## 三、需求条目

### F1 详情页数据订阅与刷新可用

**描述**：详情页改为通过 `useStore` 订阅当前投递，水合完成前显示加载态而非「不存在」。

**涉及文件**：
- `v1.0/job-compass/src/app/applications/[id]/page.tsx`
- `v1.0/job-compass/src/lib/use-store.ts`（可新增 `useApplication(id)` hook）

**验收标准**：
- 直接刷新 `/applications/[id]` 或在新标签页打开该网址，页面正常展示
- 在详情页切换状态下拉框，下拉值、看板卡片、状态时间线三处即时一致
- 删除该投递后访问旧链接，才显示「投递记录不存在」

### F2 投递编辑

**描述**：详情页与列表页提供编辑入口，可修改全部建档字段：公司、岗位、渠道、投递日期、城市、薪资、岗位链接、JD 原文、关联简历、内推人（`referrer` 独立字段）、备注。

**涉及文件**：
- `v1.0/job-compass/src/app/applications/[id]/page.tsx`（详情页编辑入口）
- `v1.0/job-compass/src/app/applications/page.tsx`（列表行操作）
- `v1.0/job-compass/src/app/applications/new/page.tsx`（`ApplicationForm` 复用为编辑形态，补 `referrer` 输入项）

**验收标准**：
- 编辑保存后，看板卡片、列表行、详情页三处展示一致
- JD 原文被修改后，详情页 JD 区块展示新内容；已生成的匹配报告保留但标注「JD 已变更，建议重新生成」
- 内推人保存后在详情页头部信息区展示

### F3 重复建档修复

**描述**：重复提示弹层中，「仍要新建」跳过本次检查并成功保存；新增「去查看」跳转已有记录。

**涉及文件**：
- `v1.0/job-compass/src/app/applications/new/page.tsx`（`handleSave` 增加跳过参数）
- `v1.0/job-compass/src/lib/store.ts`（`addApplication` 增加 `allowDuplicate` 参数，或移除静默拦截、将查重职责完全交给调用方）

**验收标准**：
- 同公司同岗位可并存两条投递
- 点击「去查看」跳转到已存在记录的详情页
- 首次命中重复时仍正常弹出提示，不默认放行

### F4 新建页提示修正

**描述**：「AI 已解析以下字段」横幅仅在 JD 解析成功后出现；手动填写模式不显示。

**涉及文件**：
- `v1.0/job-compass/src/app/applications/new/page.tsx`

**验收标准**：
- 手动填写路径全程不出现 AI 提示横幅
- 解析路径保存前横幅持续可见，点击「重新解析」返回后横幅消失

### F5 简历多段结构

**描述**：简历表单中教育背景、实习/工作经历、项目经历支持增删多条；每段经历含公司、职位、起止时间、要点列表；每段项目含名称、角色、描述、技术栈。技能保持标签输入，自我评价保持单文本。

**涉及文件**：
- `v1.0/job-compass/src/app/resumes/page.tsx`（`ResumeForm` 重构为动态列表）

**验收标准**：
- 编辑种子简历（含 1 段教育、1 段经历、1 个项目）并直接保存，段数与所有字段不丢失
- 新增第 2 段经历并填写完整，保存后卡片统计数字（教育/经历/项目/技能）同步更新
- 删除某段后保存，刷新页面结果保持
- 已存 localStorage 的旧格式数据读取不报错（缺失字段兜底为空数组/空串）

### F6 空状态收敛

**描述**：
- 无投递时：看板区域不渲染空列，仅保留首页居中引导（新建投递 / 载入示例数据）
- 有投递时：看板正常渲染各列
- 无周报时：洞察页周复盘区块显示空状态文案（如「本周还没有复盘数据，完成投递状态更新后生成」），不再展示写死的示例周报

**涉及文件**：
- `v1.0/job-compass/src/app/page.tsx`
- `v1.0/job-compass/src/components/kanban/KanbanBoard.tsx`
- `v1.0/job-compass/src/app/insights/page.tsx`（移除 `generateMockWeeklyReport` 回退）

**验收标准**：
- 空数据首屏只出现一处引导，无七列空看板
- 洞察页在无周报时不出现任何虚构数字
- 载入示例数据后看板与洞察页均正常渲染

## 四、交互与边界说明

1. **视觉沿用现状**：白卡片 + 蓝色主色（`blue-600`）、桌面左侧栏 / 移动端底部导航，不引入新组件库，不调整设计 token。
2. **数据存储不变**：仍存 localStorage，`STORAGE_KEY`（`job-compass-data-v1`）不变，用户已有数据不清空。
3. **类型定义基本不变**：`ApplicationStatus`、`StructuredJd`、`MatchReport`、`ResumeStructured` 等结构不动；`Application.referrer` 字段已存在，仅补表单入口。
4. **兼容性**：F5 涉及简历表单读写结构扩展，读取旧数据时所有数组字段兜底 `?? []`，对象字段兜底空串，保证 V1.0 存档可正常打开。
5. **AI 逻辑不动**：`mock-ai.ts` 的解析与报告生成逻辑本版不替换，仅 F2 中 JD 变更后对旧报告加提示。
